02 — Alignment Failure Catalogue

Nine failure classes, with evidence

Every misalignment on the 12 screens belongs to one of these nine classes. Fix the class once, fix it everywhere.

F·1

Width chaos — no canonical content widths

Each screen invents its own width: Add-User form ≈ 640px · Media search ≈ 480px · Library card ≈ 660px · TOTP card = full width · Update-Password form ≈ 600px · Inquiries list ≈ 480px. Right edges land on six different coordinates, so every page has a ragged silhouette and nothing lines up with anything — even within one page (Security & MFA: narrow form stacked on full-width card).

Evidence: Access Control, Security & MFA, Media, Library, Inquiries.

Fix: exactly three canonical widths — measure (560px) for forms & text, panel (760px) for focused cards, fluid for tables/grids. Nothing else exists.

F·2

Broken left axis — title and body start at different x-positions

On Profile, the avatar block and form are inset ~35px from the page title's left edge; on AI Advisor the "Add Factual Guideline" card is inset while "AI Knowledge Base" is not; on Add New User the form floats at yet another offset. The eye tracks the left edge down the page and it kinks. One page = one vertical axis: title, sections, cards, and buttons all share the same left margin.

Evidence: Profile (avatar row vs. "Settings & Security" title), AI Advisor (card vs. heading), Access Control.

Fix: one content container with one padding. Inner sections never add horizontal padding — only vertical space.

F·3

Detached actions — buttons far from what they control

Profile's "Save Changes" renders as a giant bar at the bottom of the viewport, a full scroll away from the form it saves — it reads as page furniture, not as the form's submit. Meanwhile "Create Dashboard User" is full-width of the form, "Add Guideline" / "Update Password" / "Enable Two-Factor Auth" are small left-aligned, and "Upload Media Asset" / "+ Add Resource" / "Refresh Accounts" sit top-right. Five placement logics, zero system.

Evidence: Profile (save bar at page bottom), Access Control, Media, People.

Fix: the action-proximity rule — a button lives inside the container it affects: page-level primary → header top-right; form submit → bottom-left of its form card, width auto; row actions → row menu. Never page-bottom, never full-width unless the form itself is full-width.

F·4

Stacked headers — three titles for one page

Settings pages render "Settings & Security" (title + subtitle) → then "AI Knowledge Base" (title + subtitle) → then "Add Factual Guideline" (card title) before any content. Three header tiers consume the first 280px and the user still hasn't seen an input. One page gets one H1; sections are H2 with a single purpose line; cards don't repeat what the section just said.

Evidence: AI Advisor ("Settings & Security" + "AI Knowledge Base" + card title), Profile, Security & MFA.

Fix: H1 = the rail item ("AI Advisor", "Profile"). Kill the parent "Settings & Security" page wrapper title — the rail group already says it.

F·5

Dueling empty states — two focal points, no focus

Communication screens render a top-left list ("No chats found.") and a vertically-centered "No item selected" pane at right simultaneously. The eye gets two targets in a sea of black; both are dead ends. An empty list means there is nothing to select — the detail pane shouldn't exist at all in that state.

Evidence: AI Chats, Subscribers, Inquiries ("No item selected" floating at 45% height in a bordered void).

Fix: single-focal rule — list empty → one centered empty state spanning the content area ("No chats yet — when visitors talk to the advisor, transcripts appear here"); list has items but none selected → detail pane shows a quiet hint at optical center (42% height), not geometric center of a tall box.

F·6

Stat-card labels wrap and break the row

"ACTIVE CURRICULUM TRACKS" wraps to two lines while its siblings stay on one — the four cards no longer share a baseline or a height rhythm. Long caps labels don't fit 4-up grids; that's what forced the wrap.

Evidence: Courses deck (4 stat cards, first label wraps).

Fix: sentence-case short labels ("Tracks", "Modules", "Lessons", "Tiers") at 13px — single line guaranteed; numerals share one baseline via fixed label height.

F·7

Rail overflow — nav scrolls and eats its own items

The rail renders scroll arrows (▲▼) and clips items: on AI Advisor, "Overview" and "People" have scrolled out of reach; on Inquiries, the scrollbar overlaps Library/Media. Persistent navigation that hides destinations isn't persistent. 11 items + 3 group labels must fit by design, not by scroll.

Evidence: AI Advisor (rail scrolled past Overview), Inquiries (scrollbar collision), AI Chats.

Fix: rail density pass — item height 34px, group gap 18px, user card compacted to one line; everything fits ≥ 700px viewport height with zero rail scroll. The thick custom scrollbar is removed everywhere (thin 8px overlay scrollbars only).

F·8

Orphan content on wide canvases — everything drifts top-left

On a 1440px+ viewport, Add New User puts a 640px form at the far left and abandons 55% of the canvas; Media's 480px search + one 220px card do the same; Subscribers shows one row in a void. Top-left anchoring with no max-width strategy makes every sparse page look broken rather than calm.

Evidence: Access Control, Media, Library, Subscribers, AI Chats.

Fix: content container = max-width 1200px, margin: 0 auto inside the fluid region, and sparse states use the F·5 single-focal pattern — designed emptiness at optical center, not abandonment at top-left.

F·9

Grid misalignment within composite rows

People: search (480px) + 5 pills pushed to the far right leaves an arbitrary dead gap; table columns distribute unevenly with a void between "Joined Date" and "Actions". Courses: track-list rows right-align "Foundational" while the inspector right-aligns "Preview in LMS" — two different right edges in one panel. Profile: avatar (80px) and "Profile Picture" text block sit on mismatched baselines.

Evidence: People, Courses, Profile.

Fix: one 12-column grid per page; toolbar rows use justify-content: space-between with the grid, tables get explicit column tracks (minmax), and master–detail panels share one right margin.

Also caught — 4 functional bugs to ticket now: ① chart tooltip prints "Invalid Date" (Overview); ② "Ai Chats" title-case bug → "AI Chats"; ③ "NO TRAINING RULES RECORDED." still all-caps (AI Advisor); ④ Profile read-only email is below readable contrast.
03 — The Layout System

Five rules that place everything

Every screen in the admin is assembled from the same shell, the same container, and the same three widths. When placement is systemic, alignment stops depending on whoever built the page.

Rule 1 — The shell contract

RegionSpecNotes
Railwidth 248px · fixed · item 34px · group gap 18pxNever scrolls at ≥ 700px viewport height; thin overlay scrollbar below that
Status barheight 52px · padding-inline 32pxLeft edge = content container's left edge (shared axis)
Content regionpadding 40px 48px 64px · max-width 1200px · margin-inline autoOne container per page; centers on ultrawide instead of stretching
Page grid12 cols · 24px guttersAll toolbar rows, stat rows, and panels snap to it

Rule 2 — Three canonical widths, nothing else

measure · 560px

Forms, settings cards, prose. Add User, Update Password, Profile fields, AI Advisor form — all identical width, all sharing the page's left axis.

panel · 760px

Focused single cards: TOTP setup, profile picture row, certificate preview. Used when measure is too narrow but fluid is too loud.

fluid · 100%

Tables, stat rows, media/asset grids, master–detail inspectors, charts. Fills the 12-col container, snaps to its columns.

Rule 3 — One left axis per page

Page title, every section heading, every card, every form, and every primary button share the container's left margin. Inner elements are indented only as content inside a card (24px card padding), never as independent floats. When this rule holds, the ragged-right problem disappears because right edges follow from the three canonical widths.

Rule 4 — Action proximity map

Action affects…Lives at…Example
The whole page / collectionHeader row, top-right, on the title's baseline+ Add Resource · Upload Media Asset
A formBottom-left inside the form card, auto width, 24px from last fieldSave Changes · Create Dashboard User · Add Guideline
A sectionSection header row, right sideEnable Two-Factor Auth → moves into the TOTP card header
A row / itemRow's "⋯" menuReset password · Revoke · Delete
Nothing visible (Refresh)Banned — auto-refresh or pull-to-refresh"Refresh Accounts" is deleted

Rule 5 — Vertical rhythm & focal placement

  • Stack: H1 block → 32px → toolbar row → 24px → first panel → 32px between panels. No exceptions, no extra dividers.
  • Exactly one H1 per page (the rail item's name). Sections are H2 + one purpose line. Cards have no titles that repeat their section.
  • Empty states sit at optical center — 42% of the container height — one per screen, with one sentence and one action.
  • Master–detail: list column fixed 380px, detail fluid; both panes share top and bottom edges; no detail pane when the list is empty.
  • Footer furniture (scrollbars, stray save bars) never occupies the page bottom — sticky elements only when the form is dirty.

06 — Drop-In CSS Foundation

The placement system as code

Hand this to whoever owns the admin stylesheet. It encodes Rules 1–5; page templates then compose from these primitives.

/* ---- Layout tokens ---- */
:root {
  --rail-w: 248px;
  --statusbar-h: 52px;
  --content-max: 1200px;
  --content-pad-x: 48px;
  --w-measure: 560px;   /* forms, prose */
  --w-panel: 760px;     /* focused cards */
  --gap-section: 32px;
  --gap-block: 24px;
}

/* ---- Shell: one container, one axis ---- */
.admin-main {
  margin-left: var(--rail-w);
}
.page {
  max-width: var(--content-max);
  margin-inline: auto;          /* centers on ultrawide (fixes F·8) */
  padding: 40px var(--content-pad-x) 64px;
}
.page > * + * { margin-top: var(--gap-section); }  /* vertical rhythm */

/* ---- Header: one H1, actions on its baseline ---- */
.page-header {
  display: flex; align-items: baseline;
  justify-content: space-between; gap: 16px;
}
.page-header h1 { font-size: 28px; }        /* no parent title (F·4) */
.page-header .purpose { color: var(--night-mut); font-size: 14px; }

/* ---- Canonical widths (fixes F·1, F·2) ---- */
.measure { max-width: var(--w-measure); }
.panel   { max-width: var(--w-panel); }
.fluid   { width: 100%; }
.measure, .panel { margin-left: 0; }   /* never inset from the axis */

/* ---- Form card: submit lives inside (fixes F·3) ---- */
.form-card { padding: 24px; border: 1px solid var(--night-2); border-radius: 10px; }
.form-card > * + * { margin-top: 20px; }
.form-actions { display: flex; justify-content: flex-start; } /* bottom-left, auto width */

/* ---- Toolbar rows snap to grid (fixes F·9) ---- */
.toolbar { display: flex; justify-content: space-between; gap: 16px; }
.toolbar .search { width: 320px; }

/* ---- Stat row: labels never wrap (fixes F·6) ---- */
.stats { display: grid; grid-template-columns: repeat(auto-fit, minmax(160px, 1fr)); gap: 16px; }
.stat .label { font-size: 13px; white-space: nowrap; text-transform: none; }
.stat .value { font-size: 32px; font-variant-numeric: tabular-nums; }

/* ---- Master–detail (fixes F·5) ---- */
.split { display: grid; grid-template-columns: 380px 1fr; gap: 0; }
.split .detail:empty, .split[data-list-empty] .detail { display: none; }
.empty-focal {                                  /* single focal, optical center */
  min-height: 52vh; display: grid; place-content: center;
  justify-items: center; gap: 8px; text-align: center;
  padding-bottom: 10vh;                       /* pushes to ~42% */
}

/* ---- Rail: fits without scrolling (fixes F·7) ---- */
.rail-item { height: 34px; }
.rail-group { margin-top: 18px; }
.rail { scrollbar-width: thin; }            /* thin overlay only */

Sequence and gate

  • Day 2: rail density pass (F·7) + Settings family (Profile, Security, AI Advisor, Access Control — all measure-width forms)

  • Day 4: Content family (Courses, Library, Media — stats, grids, inspector)

Alignment QA checklist (every screen)

One left axis: title, sections, cards, forms share x
Only three widths in play: 560 / 760 / fluid
Exactly one H1; no stacked parent titles
Every button within the container it affects
One empty state, at 42% height, with next action
Rail fits without scroll at 700px viewport height
Stat labels single-line; numerals share baseline
No content orphaning at 1920px (container centers)
Border nesting ≤ 1 on split panes, ≤ 2 anywhere
Scrollbars thin; no scroll arrows anywhere
Definition of done: screenshot any admin page, draw a vertical line at the title's left edge — every element on that page touches the line or lives inside something that does. Ragged edges gone; actions adjacent; one focal point per screen.
